# Поколения автомобилей

Каталог марок, моделей и поколений берётся из публичного каталога Дрома и хранится
в PostgreSQL. Нормализатор общий для всех марок: отдельные списки поколений для
BMW, Volvo или других производителей не нужны. Отсутствующие поколения выбранной
модели загружаются автоматически; кеш обновляется через 7 дней. При сетевой ошибке
используется существующий каталог, повтор загрузки ограничен паузой.

## Сопоставление

В объявлении сохраняются единый `generation_key`, название, коды кузова и
`generation_evidence` с исходным обозначением, площадкой и способом сопоставления.
Приоритет: точная ссылка на поколение Дрома, запись каталога, код кузова/шасси,
явный период выпуска, затем номер поколения внутри конкретной модели.

Номера площадок могут отличаться. Например, Camry XV40 обозначается как VI на
Auto.ru и как 7 поколение на Дроме:

- [Auto.ru](https://auto.ru/catalog/cars/toyota/camry/2309567/2309568/specifications/2309568__20501352/)
- [Дром](https://www.drom.ru/catalog/toyota/camry/g_2006_1075/)

Различия нумерации обучаются отдельно для площадки и модели по уже подтверждённым
кодам кузова, ссылкам и периодам. Конфликтующие номера не дают автоматического
совпадения. Основное поколение, первый и второй рестайлинг имеют разные ключи.
В каталог также входят коды шасси и периоды выпуска для разных рынков.
Официальные ссылки Дрома на модель с альтернативным названием ведут в её общий
каталог поколений без создания дублей.

Одного года автомобиля недостаточно. Без явного поколения или при неоднозначных
данных ключ остаётся пустым. Такое объявление доступно в поиске марки/модели,
но не проходит фильтр конкретного поколения до уточнения карточки. Чужая модель
и неизвестный код кузова не заменяются похожим вариантом.

Поиск по поколению использует индекс PostgreSQL. Нормализация страницы работает
с одним загруженным индексом каталога, без запросов в сеть для каждой машины.
Выбор пользователя сохраняется при изменении названия поколения в каталоге.

## Обновление существующей базы

Команды выполняются из `reference-parser-daa/` при работающем Docker:

```powershell
# Каталоги для всех марок/моделей, встречающихся в объявлениях.
docker compose exec -T bot python manage.py sync_generation_catalog

# Только нужная модель; принудительно обновить кеш.
docker compose exec -T bot python manage.py sync_generation_catalog --make toyota --model camry --force

# Предварительный отчёт без записи.
docker compose exec -T bot python manage.py normalize_generations

# Пересопоставить объявления по обновлённому каталогу.
docker compose stop parsers
try {
    docker compose exec -T bot python manage.py normalize_generations --apply
} finally {
    docker compose up -d parsers
}
```

Массовое обновление сохраняет цены, даты публикации, первого появления и последнего
сбора. Сборщики останавливаются на время записи, чтобы не менять те же объявления
одновременно. Telegram-бот может продолжать работу.

`sync_generation_catalog --all` доступен для полной предварительной загрузки
всего каталога. Для обычной работы достаточно моделей из базы и автоматической
загрузки выбранных моделей. Ошибки отдельных моделей выводятся в отчёте; их можно
повторить указанной командой после восстановления источника.
