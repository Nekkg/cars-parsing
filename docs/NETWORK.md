# Раздельные подключения через Karing

В .env этого ПК настроено:

```dotenv
TELEGRAM_PROXY_URL=http://host.docker.internal:3066
SOURCES_PROXY_URL=http://host.docker.internal:3065
```

Порт 3066 — VPN-выход Karing; 3065 — прямой выход. Оба проверены из Docker.
host.docker.internal — адрес Windows-хоста из контейнера, не адрес стороннего сервера.
Karing должен работать. Режим системного прокси Windows не используется приложением:
Telegram и источники явно выбирают разные подключения. Если Karing выключен,
эти подключения перестанут работать. Пустые значения переключают соответствующий
клиент на прямое соединение без прикладного прокси; это не отменяет системный TUN.

Существующие настройки Karing, подписки и правила остальных приложений не менялись.
После изменения адресов перезапустите контейнеры. Для смены прокси браузерным
источникам нужна новая сессия Selenium (остановить parsers, перезапустить chrome_driver,
затем запустить parsers).

```powershell
docker compose up -d --force-recreate bot web parsers
```

Проверка соединений (не выводит токен):

```powershell
docker compose exec web python -m scripts.diagnostics.check_network
```

Avito может ограничивать также прямой домашний IP. Правильный маршрут не гарантирует
отсутствие HTTP 429 или капчи. При ограничении сборщик делает паузу; страница доступна
в http://localhost:7900/ (Connect, пароль secret) для ручной проверки. Это браузер
именно сборщика, а не отдельная сессия обычного Chrome.

Простые варианты при сохраняющейся блокировке: прекратить частые проверки и дождаться
снятия ограничения, пройти предложенную проверку вручную, либо использовать другое
собственное подключение (например мобильный интернет) и проверить доступность сайта.
Не следует включать бесконечные повторы или считать страницу ограничения пустой выдачей.
